# slow_dedup

На графике flamegraph видно что значительную часть процессорного времени занимает сортировка ~36%.
Также внутрений цикл с проверкой пройденных элементов растет от размера входных элементов и в текущем тесте отнимат ~18% процессорного времени.

# slow_fib

На графике flamegraph видно что значительную часть процессорного времени сьедают повторные вызовы функции slow_fib. Это возникает из - за
повторных вызовов вычисления на больших числах.
